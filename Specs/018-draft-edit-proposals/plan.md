It is stored in the written file so a later run compares exactly rather than re-deriving. **Why the request and not the ids:** naming only the evidence ids was blind to three things that change what gets sent — a record's body being edited, a newly related note being pulled in, the skill file changing — so a materially different request landed on the same name and was reported as one you had already made. ## 1. Outcome

A maintainer with a corroborated failure record runs one command and gets a reviewable, content-anchored draft edit to their skill file — grounded only in what was actually observed, with nothing applied and nothing committed. This is Northstar gap #2 ("AI-assisted fix suggestion") made executable, and the *Suggest* step of the loop.

## 2. Scope

**In:** the `suggest` command; evidence resolution (findings + linked friction); prompt assembly; the one-shot drafting call; response parsing; exact-once anchor validation; the `skillet.proposal/1` writer; human + `--json` rendering; `-n` preview.

**Out (tracked §8):** applying edits to any tree (F42), proving by A/B (F43), lifecycle marking (F44), held-out proof (F45), the run/triage selectors, raw corrective-turn mining (Phase 8), and format graduation to frozen.

## 3. CLI contract

```
skillet suggest <skill> --from <evidence-id>... [--out <name.json>] [-n|--dry-run] [--yes] [--json]
```

- `<skill>` — **exactly one** discovered skill. **Required** (A20): the shared selection helper returns **every** discovered skill when handed an empty list (verified), so a missing argument must be usage/2 — never "draft for all skills". Unknown name ⇒ usage/2, as `lint`/`doctor`/`triage`.
- `--from <evidence-id>` — repeatable, **required** in v1. An id may name **either** a machine-mined finding or a hand-written friction note (D1); it is looked up at **`<skills-root>/<skill>/evaluations/findings/<id>.md`**, then **`<skills-root>/<skill>/evaluations/friction/<id>.md`** (corrected review 2026-07-29 — the earlier wording reversed the components as `evaluations/<skill>/…`, which resolves nothing; the skill folder comes first and *contains* `evaluations/`, per the code, the `init` scaffolding, and the design doc's file tree). Absent from the first folder is a **plain lookup miss, never reported**; absent from **both** is usage/2, naming the id and **listing the ids that do exist** (matching the unknown-skill error; the set is small by design, so the full list is the targeted answer — corrected 2026-07-30 from the earlier "near-misses" wording, which implied similarity matching the tool does not do). Present in **both** is refused as **ambiguous** (usage/2, naming both files) rather than silently resolved by order — matching this project's existing refuse-on-ambiguity rule for a passage that matches twice, and the least-astonishment principle that a system should error rather than quietly pick one of two meanings. No `kind:id` prefix syntax ships: ids are date-prefixed slugs in sibling folders so collisions should be rare, and the prefix form is purely additive if they prove otherwise.
- `--out <name.json>` — filename **inside** `.skillet/proposals/` (D3); a path separator or `..` is usage/2.
- `-n|--dry-run` — print the plan (evidence resolved, target file, estimated prompt size, model, prompt version) and exit 0 **without any model call**.
- `--yes` — proceed past the **spend ceiling** (D5). Without it, an estimate over the built-in 256 KiB ceiling refuses at exit 5 (gate) rather than spending. The command **never prompts**, so this flag is the only spend interaction and behaves the same in a terminal and in CI.
- `--json` — `skillet.suggest/1` result envelope (what was drafted + where written); the proposal file itself is `skillet.proposal/1`.

**Config (D8):** one optional key, `suggest.model`. The drafting model resolves `suggest.model` → `judge.model` → **refuse usage/2** (`run`'s existing "name a model explicitly" error). The binary resolves through `run`'s chain (`SKILLET_CLAUDE_CODE_BIN` → `harness.claude-code.path` → `PATH`); unresolvable ⇒ environment/3. The spend ceiling is a **built-in constant**, not a setting — `--yes` is its escape hatch.

Human closing line names the review step and — only once F42 registers it — the apply step (A1).

## 4. Data flow (shell steps do I/O, core steps are pure — the `AnalysisKit` split)

1. **(shell)** discover project → resolve skill → **rebuild the skill path lexically under `projectRoot/skillsRoot/<skill>` and assert containment** (A10, the `TriageCommand` guard) → **free-before-paid lint gate in no-behavioral-tests mode** (A5) → **resolve the model** `suggest.model` → `judge.model` → else usage/2, and the binary via `run`'s chain → else environment/3 (D8). All of this is free and happens before any spend.
2. **(shell — in the executable, never the kit; §6)** resolve each `--from` id against **`<skills-root>/<skill>/evaluations/findings/<id>.md`** then **`<skills-root>/<skill>/evaluations/friction/<id>.md`** (either kind — D1). **Existence is probed first**, so "absent here" is a plain miss, not a reported problem: absent from both ⇒ usage/2; present in both ⇒ ambiguous ⇒ usage/2 naming both. For the one file that resolves, read via `SafeFile.readPlainText` and decode via `EvidenceFrontmatter.decode(text, filename: <file name>)` — **passing the filename is required**, it drives the built-in `id`↔stem cross-check. **A named record must fully resolve or the command fails (A17):** any read refusal (symlink/special/unreadable/oversized) or decode failure on an id *you asked for* is `EDDError.invalidArtifact` ⇒ **exit 4** with the reason — **not** the disclose-and-skip posture of the bulk folder scan, which would draft from incomplete evidence while reporting success.

## 5. Two formats: the drafted file (provisional) and the command summary (stable)

### 5a. `skillet.proposal/1` — the drafted file on disk (PROVISIONAL — D4)

**On-disk shape:** `schema`, `id` (**`<run-date>-<skill>-<fingerprint>`** — D7), `skill`, `motivation: [evidence-id]` (the ids you named), `expected: [eval-id]` (**copied from those records' `eval` fields, never model-supplied; empty is normal** — D6/A14), `model`, `prompt_version`, `request_fingerprint` (**the same 8 hex chars as the id's tail, stored so a later run compares exactly instead of re-deriving** — D7), `edits: [EditProposal]`.
Per edit: `path` (D4a — defaults to the skill's `SKILL.md`; **this version rejects any other value** at parse time), `skill_md_lines`, `current_excerpt`, `proposed_text`, `rationale`, `addresses`.

**Codec (corrected, review 2026-07-29 — the earlier wording would have written the key twice).** `ProposalSet` conforms to `SchemaIdentified` with `static let schema = "skillet.proposal/1"` and **declares no `schema` stored property / coding key**. The shared encoder's `Envelope` already stamps `schema` and then merges the payload's own fields, so a payload that also encoded `schema` would emit it twice (last-wins, silently clobbering the envelope's value). Every sibling format here does it this way — `TriageReport` declares the id statically and carries no such field (verified). The file on disk is unchanged; only the type is. Decoding a hand-authored file that *does* spell out `schema` still works: the decoder ignores keys the type doesn't model (the same reason the sibling format's round-trip test passes).

Golden fixture enumerates **every** field (the F8 rule: an omitted field is an unenforced shape). Documented as provisional; **graduation trigger: F42 reads it back.**

### 5b. `skillet.suggest/1` — the `--json` command summary (STABLE from day one — Q1=A)

Previously referenced but never defined (review 2026-07-29). A `SuggestResult: SchemaIdentified` payload — **report-and-point**: it says what happened and names the file it wrote; the **file is the source of truth for edit content**, never duplicated here.

`schema` (stamped by the envelope), `skill`, `proposal_id` (null on a dry run), `path` (project-relative path written; null on a dry run), `edits` (count), `motivation: [evidence-id]`, `expected: [eval-id]`, `model`, `prompt_version` (which drafting instructions — the one fact a preview cannot get from the written file, because it writes none), `estimated_prompt_bytes`, `dry_run`, `disclosures: [{subject, reason}]` (anything skipped or rejected, with why).

Mirrors exactly the facts the human output prints — nothing speculative (the rule `TriageReport` already follows). **Compatibility promise: additive-only; consumers must ignore unrecognized fields.** Deliberately does **not** embed the edits: the drafted-file shape is provisional (D4), and nesting a provisional shape inside a stable one would make every future change to it a breaking change here — the cascade schema-evolution guidance exists to prevent. Golden fixture + round-trip test, same as the file format.

## 7. Test plan (red → green; every test $0 via the fixture runner — A6)

1. **Format (EDDCore):** golden fixture with all fields; round-trip; `schema` first; unknown-field tolerance.
2. **Prompt (pure):** carries finding bodies, joined friction bodies, and the skill file; deterministic for fixed inputs; stamps `prompt_version`.
3. **Parse (pure):** well-formed reply → proposals; malformed → typed error (⇒ exit 4); partial reply keeps valid edits, drops invalid with a reason.
4. **Anchor validation (pure):** 0 matches ⇒ rejected (drift); 2+ ⇒ rejected (ambiguity); exactly 1 ⇒ accepted.
5. **Observed-evidence-only (A4):** empty/unresolvable evidence ⇒ refusal **and the fake runner is never invoked** (asserted).
6. **Free-before-paid (A5):** lint-error skill ⇒ refused with no call.
7. **Preview (D5):** `-n` writes nothing, calls nothing, prints the estimate.
7a. **Spend ceiling (D5/D8):** an estimate over the built-in ceiling **refuses at exit 5 with the fake runner never invoked**; the same input with `--yes` proceeds; under the ceiling never refuses. No test ever exercises a prompt (there is none).
7b. **Single-file scope (D4a):** a reply whose edit names a `path` other than the skill's `SKILL.md` is rejected with a stated reason and never written; an edit naming `SKILL.md` is accepted.
7c. **Directory creation (A1):** on a project with no `.skillet/proposals/`, the first draft creates it and writes; a second draft with the same name is a disclosed refusal, not a clobber.
7d. **`expected` provenance (D6):** built from evidence whose records carry `eval` ⇒ those ids, sorted + de-duplicated; evidence with none ⇒ **empty**; a reply that *includes* an `expected` ⇒ ignored (asserted, not merged).
7e. **Set id (D7):** the fingerprint covers **the assembled request**, not just the ids naming its parts — so the same request drafted twice in a day gives a byte-identical id (order-independent, since the request's evidence sections sort first), while a changed evidence id, an edited record body, a newly related note, or a changed skill file each give a different one. A different run date also gives a different id: the date is part of the id, so "same request" is compared through the stored `request_fingerprint`, never by matching ids. Stable across processes (hand-rolled FNV-1a, 8 hex chars, *not* Swift's per-process-seeded `Hasher`).
7f. **Exit codes (A7):** unknown skill / unknown id / no `--from` ⇒ 2; lint-error skill ⇒ 2 with no call; **a different draft (or an unreadable/over-size file) already holding the requested name ⇒ 2, nothing overwritten** — you asked for a draft and got none, so success would let a script carry on as though one existed; over-ceiling without `--yes` ⇒ 5; undecodable evidence ⇒ 4. An *identical* draft already present is **0** — that is the state you wanted.
7g. **Evidence read (A3):** a refused read is **disclosed** (not silently dropped); a file whose declared id disagrees with its filename is rejected by the decoder's cross-check.
7h. **Model resolution (D8):** `suggest.model` set ⇒ used; unset with `judge.model` set ⇒ falls back to it; **neither ⇒ exit 2 with no call**; an unresolvable binary ⇒ exit 3. The chosen model is what lands in the written file's `model` field.
7i. **Confinement (A10):** a symlinked `evaluations/` **folder** is blocked by the containment check before any read; a symlinked **`SKILL.md`/evidence file** is refused by the safe reader itself. Both asserted separately, so neither guard can regress unnoticed.
7j. **Cache safety (A1):** a symlinked `.skillet` ⇒ refuses to write; a repo with no `.skillet/.gitignore` ⇒ the file is created (`*`) **before** the draft lands, so a first-ever draft is never left un-ignored.
7k. **Lint mode (A5):** a skill with **no evals file** but valid evidence ⇒ **not** refused (the missing-tests-file error is filtered); a skill with a genuine error-tier lint finding ⇒ refused at exit 2 with no call.
7l. **Codec — no double `schema` (§5a):** the encoded file contains **exactly one** `schema` key with the right value, and the type exposes no `schema` property; a hand-authored file that spells out `schema` still decodes (unknown-key tolerance).
7m. **Command summary (§5b):** golden fixture enumerating every field + round-trip; `path`/`proposal_id` are null on a dry run and set on a real draft; **the edits are NOT embedded** (asserted, so the stable summary can't drift into carrying provisional content).
7n. **Empty proof list (A14):** evidence with no linked test ⇒ `expected` is `[]` **and** the human output says no test covers this yet and what to do about it — never a silent empty field.
7o. **Either evidence kind (D1):** `--from` naming a **friction note** drafts successfully and records that id as motivation — the same as naming a machine-mined finding; both kinds reach the prompt.
7p. **Lookup + ambiguity (D1):** an id in neither folder ⇒ usage/2 with near-misses; an id in **both** ⇒ usage/2 naming both files, **with no model call**; an id absent from the first folder but present in the second resolves cleanly and produces **no disclosure** (the reporting bug this round fixes).
7q. **Fingerprint inputs (A16):** same evidence + same model + same prompt version ⇒ identical id; **changing only the model ⇒ a different id** (so the re-draft is not refused as a duplicate).
7r. **Named-evidence failure is fatal (A17):** a named id whose file is a symlink / unreadable / undecodable ⇒ **exit 4 naming it, with no model call** — explicitly *not* skipped-with-a-note.
7s. **Model service gate (D9):** explicit drafting model + a foreign grading service ⇒ **proceeds**; no drafting model + foreign grading service ⇒ **usage/2 naming both settings**, no call; borrowed model ⇒ the human output says it was borrowed.
7t. **Reply normalization (D10):** a reply wrapped in one code fence parses; a reply with leading prose **fails at exit 4** (not salvaged); an empty reply fails at exit 4 with an excerpt; **no second call is ever made**.
7u. **Cache guard targets this command's path (A1):** a symlinked `.skillet/proposals` refuses; a symlinked `.skillet` refuses.
7v. **Skill selection (A20):** a missing skill argument ⇒ usage/2 (never every skill).
7w. **Instructions match validation (D11):** the assembled prompt contains the scoped, positive principle and **no** "move it to a reference file" phrasing — asserted on the prompt text, so the contradiction cannot silently return.
7x. **Exit classes (A7):** a resolved model program exiting non-zero ⇒ **3**; a missing/unreadable `SKILL.md` ⇒ **3**; a named evidence file that is unreadable ⇒ **4** (all three asserted together, so the distinction can't drift).
7y. **`--out` shape (A21):** a name without `.json` ⇒ usage/2; with `.json` ⇒ accepted; a separator or `..` ⇒ usage/2.
8. **Write rules (A8):** default path; `--out` confined to the proposals dir (separator/`..` ⇒ usage/2); existing file ⇒ disclosed refusal, never clobbered.
9. **Untrusted reads (A10):** a symlinked evidence file is refused **and disclosed**, never followed.
10. **Integration:** end-to-end draft → file on disk → exit 0; `--json` carries its schema; unknown skill/id ⇒ 2.
